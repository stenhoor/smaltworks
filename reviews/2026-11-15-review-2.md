# Review, round 2, 2026-11-15

A second, deeper pass over the smalt repositories: dependencies between them, CI, the copied site kit, the
documentation standard, branches and issues. Read-only: nothing in any repository was changed. smaltdf is reviewed from
`main`. The suggestions here are for the owner to decide on; none is acted on yet.

## 1. The platform isn't unified at run time

Until 0.9.0 is published, repositories install each other from commits listed in `packed.json`
(`scripts/fetch-packed.mjs`, identical in 12 repositories). Each repository pins its own commits:

| Package | Different commits pinned across the family |
| --- | --- |
| smaltdb | 7 (`b82ad6f`, `01ba9e0`, `fda57d2`, `bbde3bd`, `0ac2192`, `062b248`, `079890a`) |
| smaltkit (via `github:` in package.json) | 7 (`b949bc8`, `e18b2ed`, `3a6f128`, `9966247`, `94b1863`, `82b958b`, and a fork) |
| @smaltworks/smaltql | at least 5 |

So each app is built and tested against a different engine. Also:

- **smaltgl** installs smaltkit from **`apbeers/smaltkit`** and smaltcy from **`apbeers/smalt-graph-db`**: forks
  outside `stenhoor`. It also takes smaltdb from npm at `^0.8.3`, the old unscoped release.
- **smaltkit** takes smaltty at a tag (`v0.14.0`); everything else uses commits.
- **smaltnb** pins `smaltql` by its old name.

**Suggestion:** a **release train**. smaltworks keeps one compatibility set: the exact commit (and later the version)
of each package that goes together. Repositories move to the next set together, in one round of PRs, instead of each
bumping on its own. After 0.9.0 the set becomes version ranges.

## 2. 0.9.0 is the critical path

The package renames, the end of `packed.json` and `fetch-packed.mjs`, smaltgl's `^0.8.3`, and smaltnb's old name are
all fixed by the 0.9.0 publish (smaltdb#36, "reach 0.9.0", in progress since 2026-11-03).

**Suggestion:** treat 0.9.0 as the first release train, and hold new product work that adds pins until it ships.

## 3. Node: claimed, not tested

Every CI tests on Node 22 only, while most `package.json` files claim `>=20`.

**Suggestion:** the standard is `>=22.18`, what CI tests (and the first 22 release that strips TypeScript types
without a flag, which several repositories rely on).

## 4. The copied site kit has drifted

The site kit is meant to be copied unchanged. Against smalt-brand's `themes/vitepress/`:

- `smaltdb.css` differs in 12 of 13 sites (only smaltkit's matches).
- `smaltworks.ts` differs in smaltdf, smaltgl and smaltts; `playground.ts` and `agents.ts` differ wherever they are
  copied.

This is smalt-brand's to fix, but it is the same problem as section 1: copies drift.

**Suggestion (for smalt-brand):** ship the site kit the way smaltkit is shipped, as a pinned package, not as copies.

## 5. The documentation standard is partly adopted

| | Repositories |
| --- | --- |
| All four sections, playgrounds and docs for agents | smaltcy, smaltdf, smaltml, smaltql |
| Partly | smaltgl, smaltts, smaltty (no quick start); smaltkit (no getting started; a kit may not need one) |
| Mostly not yet | **smaltdb** (reference only), smaltbi, smaltfl, smaltnb, smaltui |

**Suggestion:** a conformance table in smaltworks (repository × standard), updated by each review, so adoption is
visible without chasing it.

## 6. Branches pile up

Open branches: smaltdb 186, smalt-brand 71, smaltnb 49, smaltql 47, smaltdf 33, smaltkit 29, smaltui 23. Most are
session branches whose PRs merged long ago.

**Suggestion:** a standard: GitHub's "Automatically delete head branches" on in every repository (a setting), and a
one-time cleanup of branches already merged.

## 7. Cross-project work is tracked in a product repository

smaltql has the tracking issues for ADR 0024 (smaltml, smaltql#30) and ADR 0025 (smaltai, smaltql#31, #32), which are
not about SQL.

**Suggestion:** issues for tier 1 work live in smaltworks; WORK.md stays the register.

## 8. Cross-repository facts go stale in `CLAUDE.md` files

- smaltdb's `CLAUDE.md` says smaltui and smaltbi depend on the npm package `smaltdb` `^0.8.3`; both actually use
  pinned commits.
- smaltfl's `CLAUDE.md` is 513 lines, with its own map of the family.

**Suggestion:** facts about other repositories live once, in smaltworks (the family table, plus a dependency map), and a
repository's `CLAUDE.md` keeps only its own rules.

## 9. Decisions waiting

Ten ADRs are `proposed`, some since 2026-11-08: smaltfl 0010–0013 and 0015, smaltbi 0008, ADR 0025 and 0026 (smaltai),
0033 (property graphs), 0035 (smaltml-simd).

**Suggestion:** a decision queue in smaltworks, listing what waits on the owner, oldest first.

## 10. Still open from round 1

Test runner (vitest in most, `node --test` in smaltbi, smaltkit, smaltty: perhaps on purpose, since vitest is outside
code), the copyright line, smalt-brand's missing licence, the empty repositories, and smaltgl's place in the family.
